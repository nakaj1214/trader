## 3. 判断の材料
1. **無料で、point-in-time で、過去検証もできるのは EDINET の直接取得だけ。** 大量保有報告（5%ルール）の提出は、機関投資家やアクティビストの参入を示す catalyst になりうる。B1 の基盤（日付ごとの取得・キャッシュ・reconstruct_scan）と同じ方式で、過去の提出を復元し、候補の前後に提出があったかを調べられる。まず、**診断用の特徴量として記録するだけ**にして、効果は forward と過去検証で確認する（戦略は変えない）。
2. **TDnet は最も直接的だが、月7,150円〜かかる。** 先に EDINET で「catalyst の記録 → 検証」の流れを作り、価値が見えてから判断するのが安全。
3. **Light（1,650円/月）は、遅延の解消が主な価値。** B1 の標本は、lag の差を判定するには足りなかった（独立取引 18件と10件）。効果は不明のまま、費用は小さい。forward の標本が溜まる前に切り替えれば、遅延のない状態の snapshot を蓄積できる（ただし Free の snapshot とは別の系列になる点に注意）。
4. **Standard（3,300円/月）は、信用残・空売り・EDINET大量保有を含む。** EDINET を直接取得すれば、Standard の主な価値は信用残・空売りだけになる。

## 4. 未確認・要確認
- TDnet アドオンの料金（5,500円/月）と対象プラン: 検索結果の要約のみ。公式で再確認する。
- EDINET の書類一覧APIの提出日時の粒度、1日あたりの書類数、取得に必要なAPIの呼び出し回数（B1 の取得のように、日付ごとに取る場合の量）: 実際に1日分を取得して確認する。
- 保有目的（純投資・重要提案行為など）は、書類の中身を読む必要がある。メタデータだけで足りるかは、実装前に1件の書類で確認する。
- Light 以上で、決算予定日の遅延が解消するか: 契約しないと確認できない。
