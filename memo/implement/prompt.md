# 保留（2026-11-19 の追加調査で見つけた問題）

[proposal.md](proposal.md)（REQ-001〜008）とは別に見つけたもの。影響が小さいので、今回は直さない。

## 1. 2月決算の会社で、うるう年の翌年度は前年比が計算されない（低・2028年まで影響なし）

- **原因**: 前年の期末日を「1年前の同じ日付」で求めている（[inflection_live.py:299](../../src/screening/inflection_live.py#L299)、`prior_year` [:417](../../src/screening/inflection_live.py#L417)）。2025-02-28 から 1 年引くと 2024-02-28 になるが、実際の期末は 2024-02-29 なので、前年の決算が見つからない。
- **影響**: 売上・営業利益の前年比と四半期の前年比が欠ける。次に起きるのは 2029 年 2 月期（2028 年の開示から）。合成データで再現済み。
- **直し方の案**: 前年の期末日を「今期の期首の前日」で求める。

## 2. フォワード検証を平日の取引時間中に手動実行すると、場中の株価を終値として扱う（低）

- **原因**: 価格の取得期間の終わりを「今日（UTC）」にしている（[rebuild_inflection_forward_validation.py:216](../../scripts/rebuild_inflection_forward_validation.py#L216)、[forward_prices.py:202](../../src/data/forward_prices.py#L202)）。平日 9:00〜15:30 JST に実行すると、未確定の当日の日足が入る。
- **影響**: その実行で保存される集計ファイル（artifact）だけ。日曜の定期実行と、価格ハッシュの保存には影響しない。
- **直し方の案**: 取得期間の終わりを、確定済みの直近の取引日にする。この関数は学習処理も使うので、両方を確認する。

## 3. 失敗通知が同時に 3 件以上重なると、待機中の通知が取り消される（低）

- **原因**: 4 つの workflow の失敗通知と watchdog が、同じ concurrency グループ（`workflow-reliability-notifications`）で動く。GitHub は同じグループで待機中のジョブを 1 つしか残さず、新しいジョブが来ると古い待機ジョブを取り消す。
- **影響**: Actions の障害明けに、遅れていた実行がまとめて失敗したときに起こりうる。毎日の workflow の未実行は watchdog が後から検出するが、失敗の原因を伝える通知は失われる。
- **保留の理由**: 通知済みの記録を 1 つのキャッシュで共有するために同じグループにしているので、分けると通知の重複など別の問題が出やすい。直すなら、記録の持ち方から見直す。
